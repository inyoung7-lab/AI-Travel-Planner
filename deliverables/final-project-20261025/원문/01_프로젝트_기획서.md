# 여행 한걸음 프로젝트 기획서

국내 여행 정보 탐색과 일정 작성을 연결하는 AI 기반 웹 서비스

## 서비스 개요

여행 한걸음은 여행지를 찾고, AI가 만든 초안을 조정하거나 빈 일정에서 직접 여행 계획을 만들 수 있는 서비스다. 여행 후에는 저장한 일정의 각 장소에 리뷰를 남길 수 있다. 지역 체험을 제공하는 호스트의 운영 기능도 함께 구성했다.

## 문제 정의

여행자는 관광지와 음식점, 숙소를 여러 화면에서 비교하고 날짜별 방문 순서를 직접 조합해야 한다. 도 전체를 대상으로 추천하면 서로 먼 도시의 장소가 한 일정에 섞일 수 있다. 일정 초안을 받은 뒤 원하는 장소를 추가하고 다시 저장하는 과정도 필요하다.

## 서비스 목표

실제 관광정보를 근거로 가까운 권역의 일정 초안을 제공한다. 사용자가 장소와 시간을 직접 조정하고 계정에 저장하도록 돕는다. 계획과 여행 기록, 장소별 리뷰를 하나의 흐름으로 연결한다.

## 검증할 가설

AI 초안과 직접 편집 기능을 함께 제공하면 일정 작성 부담을 줄일 수 있다. 준비 시간 단축과 만족도 향상은 아직 정량 측정하지 않았으며, 외부 사용자 테스트의 검증 대상으로 둔다.

| 핵심 가치 | 구현 방식 |
| --- | --- |
| 근거 있는 추천 | Supabase 관광정보와 날짜별 날씨 및 행사 활용 |
| 사용자 선택권 | AI 생성과 직접 일정 만들기 병행 |
| 다시 이어지는 여행 | 회원별 저장 일정과 찜, 지난 일정 및 리뷰 |

# 대상 사용자와 이용 시나리오

실제 인터뷰 결과가 아닌 서비스 설계를 위한 사용자 유형이다.

## 일정 초안이 필요한 국내 여행자

지역과 여행 기간은 정했지만 방문 장소를 고르는 데 시간이 드는 사용자다. 지역, 세부 지역, 이동 수단과 스타일을 입력해 AI 초안을 받고 코스를 조정한다.

## 직접 계획하고 싶은 여행자

원하는 장소가 분명하거나 지인과 여행 일정을 조합하려는 사용자다. 이름과 날짜로 빈 일정을 만든 뒤 여행지 찾기에서 원하는 일차에 장소를 담는다.

## 지역 체험을 운영하는 호스트

체험 내용과 회차, 프로필을 관리하고 체험의 차별점과 운영안을 검토하려는 사용자다. 본인 권한 범위에서 AI 기획 및 진단 기능을 사용한다.

## 대표 이용 흐름

여행지 탐색 및 찜 → AI 생성 또는 직접 일정 생성 → 장소와 방문 시간 편집 → 계정 저장과 재조회 → 지난 일정 확인 → 장소별 리뷰 작성.

## 범위 구분

여행지 탐색, 추천, 일정과 리뷰, 로컬 체험 운영을 포함한다. 결제와 숙박 예약, 항공권 구매, 실제 도로 경로 및 실시간 교통 소요 시간 검증은 핵심 구현 범위에서 제외한다.

# AI 활용 방식과 의사결정

여행 일정 생성과 호스트 체험 진단은 서로 다른 AI 실행 경로를 사용한다.

## 여행 일정 생성 워크플로우

서버는 Supabase의 관광지와 문화시설, 음식점, 숙박 후보를 조회한다. 주소와 좌표로 같은 시·군·구의 가까운 권역을 구성하고 실제 일별 예보 및 여행 날짜와 겹치는 행사 정보를 함께 전달한다. LLM은 제공된 후보 ID만 사용해 구조화된 JSON 일정을 반환한다.

## 검색 증강 생성의 적용

외부 관광정보를 DB에 저장한 뒤 조건에 맞는 정보를 검색하여 모델 입력에 넣는다. 현재는 구조화된 SQL 조회와 규칙 기반 선별을 사용하며 벡터 DB 또는 임베딩 검색을 사용했다고 설명하지 않는다.

## 호스트 체험 Agent

Supabase Edge Function은 호스트 인증과 체험 소유권을 확인한 뒤 search_existing_experiences, retrieve_local_knowledge, evaluate_experience_value, estimate_program_cost 도구를 실행한다. 일반 채팅 기반 어댑터가 JSON 인자를 생성하고 서버가 도구와 출처를 검증한다. 네이티브 function calling에 의존하지 않는다.

## 결과 통제

여행 일수와 후보 ID, 날짜 및 권역을 검사한다. 행사는 확인된 개최 기간 안에만 배치한다. 날씨 조회 실패와 예보 범위 밖의 날짜는 미반영 상태를 표시한다. 직선거리와 계절 키워드는 도로 이동시간이나 실제 단풍 절정, 제철 식재료 판매를 보증하지 않는다.

## 사용자의 최종 판단

AI 결과임을 화면에 표시한다. 호스트의 운영안은 검토 후 편집란으로 복사하고 별도 저장한다. 여행자는 직접 장소를 수정하고 저장할 수 있다.

참고: 근거: server/itinerary.js, server/itineraryContext.js, supabase/functions/local-eum-agent/agent-core.mjs 및 docs/local-eum/ai-agent-runbook.md.

# 기술적 접근과 데이터 구조

React 화면, Express API, Supabase 및 외부 정보 서비스를 조합했다.

## 데이터 중심 구조

회원 인증은 Supabase Auth가 담당한다. 여행지와 상세 정보, 일정, 찜, 커뮤니티 데이터는 PostgreSQL에 저장한다. 개인 데이터에는 RLS를 적용하고 서버는 전달받은 JWT의 실제 사용자를 확인한다.

## 관광정보 수집

TourAPI 전체 페이지를 수집한 뒤 수정 시각과 원본 해시를 비교하여 변경분을 갱신한다. 체크포인트로 중단 후 재개할 수 있다. 기준 검증에서 원본 69,208건과 관광지 분류 12,556건을 확인했다. 서로 다른 분류와 비공개 원본을 동일한 관광지 수로 합산하지 않는다.

## 일정 저장

AI와 직접 만든 일정은 travel_itineraries의 JSONB payload를 공유한다. 직접 일정은 source=manual과 draft 상태로 빈 날짜를 저장한다. 편집 저장은 updated_at 조건으로 다른 화면의 변경을 덮어쓰지 않도록 검사한다.

| 기술 | 선정 이유 |
| --- | --- |
| React 19 및 Vite | 화면별 상태 관리와 빠른 프런트엔드 개발 |
| Express 5 | 외부 API 키 보호와 생성 결과 검증 |
| Supabase Auth 및 PostgreSQL | 인증과 관계형 데이터, 소유권 정책 통합 |
| Codyssey OpenAI 호환 API | 제공된 후보에 근거한 일정 및 체험 기획 |
| TourAPI 및 Open-Meteo | 관광정보와 실제 예보를 분리하여 활용 |

# 성과 평가와 남은 수행 범위

구현 완료와 검증 예정 항목을 구분해 평가한다.

## 현재 확인된 결과

직접 일정 생성과 일차별 장소 추가, 순서 및 시간 편집, 저장 후 재조회가 실제 DB 연동 검사에서 통과했다. 실제 AI 생성, 찜 저장 및 취소, 지난 일정과 장소별 리뷰 및 회원 간 접근 제한도 확인했다.

## 사용성 평가 지표

일정 생성과 장소 추가, 저장 및 재조회 작업의 완료 여부, 소요 시간, 막힌 단계와 이유를 수집한다. 추천 동선의 납득도와 편집 편의성을 1~5점으로 평가하고 자유 의견을 남긴다. 목표값은 테스트 전에 합의하며 현재 만족도 수치를 만들지 않는다.

## 운영과 품질 위험

지도는 위치 관계를 보여주며 도로 경로를 계산하지 않는다. API 실패와 호출 한도, DB 조회 지연이 발생할 수 있다. 정기 동기화는 현재 로컬 실행 환경에 의존하며 공개 운영 시 서버 스케줄러로 옮겨야 한다.

## 별도 수행 항목

GitHub 업로드와 외부 접근 가능한 서비스 배포는 별도 작업이다. 실제 사용자 5명 이상 테스트의 참여 기록, 설문과 반영 결과는 추가 수집 대상이다. 개발 중 피드백 및 자동 검증은 이 외부 사용자 요건을 대신하지 않는다.

## 실행 점검

발표 전 배포 주소에서 로그인, 새로고침 경로, API 연결과 환경변수를 확인한다. 개인정보 안내 및 회원가입 동의 이력 저장은 현재 구현과 공개 운영의 필요한 범위를 검토한다.
