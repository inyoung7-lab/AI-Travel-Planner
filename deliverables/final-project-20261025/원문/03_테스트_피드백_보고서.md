# 여행 한걸음 테스트 및 피드백 보고서

개발 중 확인한 결과와 외부 사용자 검증 계획

## 검증 범위

2026-10-25 기준 코드와 실제 Supabase 개발 프로젝트에서 확인한 결과다. 자동 검증, 실제 API·DB 연동 검사와 개발 중 사용성 의견을 분리한다.

## 중요한 구분

이번 대화의 개선 요청은 개발 중 사용성 피드백이다. 최소 5명 외부 사용자 테스트의 참여 기록이나 설문 결과로 간주하지 않는다. 해당 요건은 아래 실행 계획과 양식으로 별도 수집한다.

## 화면 검증 한계

브라우저 자동 연결이 응답하지 않아 최근 변경 전체를 클릭하며 확인하지는 못했다. 빌드 통과와 실제 API·DB 저장 성공은 모든 화면 배치와 사용성을 증명하지 않는다.

| 검사 묶음 | 결과 | 확인 범위 |
| --- | --- | --- |
| Supabase 및 일정 자동 검증 | 40 / 40 통과 | 권한·일정·동기화·회원가입 등 |
| 탐색 및 추천 자동 검증 | 40 / 40 통과 | 검색 해석·추천·쿠키·이동 경로 |
| 장소 상세 자동 검증 | 6 / 6 통과 | 사진 연결·동명 장소·입력 검사 |
| 실제 DB 연동 검사 | 2 / 2 통과 | 실제 저장과 권한 및 AI 생성 |
| 호스트 Agent 모의 검사 | 16 / 16 통과 | 도구 실행·출처·비용·권한 |

참고: 테스트 묶음 간 일부 항목은 중복 실행된다. 총합을 독립적인 시나리오 개수로 해석하지 않는다. Agent 모의 테스트는 실제 모델 품질 검증을 대신하지 않는다.

# 개발 중 피드백과 반영 결과



| 관찰 또는 요청 | 적용한 변경 | 확인 방법 |
| --- | --- | --- |
| AI 일정을 나의 여행에서 볼 수 없음 | 저장 목록 통합과 다시 열기 연결 | 실제 계정 저장·재조회 |
| 하트가 화면 색만 바꿈 | 회원별 Supabase 찜 저장·취소 | 멱등 저장·취소 연동 검사 |
| 일정과 찜이 늘어나 화면이 길어짐 | 일정 3개, 찜 6개 단위 페이지 | 빌드 및 목록 분할 코드 검사 |
| 같은 과거 일정이 장소마다 반복됨 | 여행 하나로 묶고 전체 일정 상세 제공 | 저장 payload와 상세 연결 확인 |
| 각 방문 장소에 후기를 남기고 싶음 | 일정 상세에서 장소 선택 리뷰 연결 | 리뷰·별점 저장 검사 |
| 경남 추천이 먼 도시를 오감 | 시·군·구와 이동 반경으로 후보 선별 | 실제 거제 생성 및 좌표 검사 |
| 지난 날짜로 새 일정 생성 가능 | 화면 최소 날짜와 서버 검증 | 한국 날짜 경계 및 400 검사 |
| AI 없이 직접 일정을 만들고 싶음 | 빈 일정 생성과 날짜별 장소 추가·편집 | 실제 DB 생성·편집·재조회 |

참고: 위 내용은 실제 개발 대화의 요청을 요약했다. 만족도나 시간 단축 성과를 측정한 결과는 아니다.

# 최소 5명 사용자 테스트 실행안

외부 사용자에게 동일한 과제를 제시하고 실제 작업 결과를 수집한다.

## 참여와 진행

국내 여행을 준비한 경험이 있는 5명 이상을 모집한다. 이름 대신 P01~P05 등 참여 코드를 사용하고 화면 녹화나 연락처 수집이 필요한 경우 목적과 보관 범위를 안내한다. 한 사람당 약 15~20분을 계획한다.

## 작업 A 탐색과 찜

원하는 지역의 여행지를 찾고, 상세 정보를 확인한 뒤 2곳을 찜한다. 나의 여행에서 찜한 곳을 찾고 한 곳을 해제한다.

## 작업 B AI 일정

지역과 날짜를 입력해 AI 일정을 만든다. 선택한 권역과 동선을 설명해 보고, 결과를 저장한 뒤 다시 연다.

## 작업 C 직접 일정

빈 2일 일정을 만든다. 두 장소를 2일차에 담고 방문 시간을 지정한 뒤 순서를 바꾸고 저장한다. 새로고침 후 내용을 확인한다.

## 작업 D 여행 기록

준비된 과거 일정의 전체 코스를 열고 특정 장소의 리뷰 작성 화면으로 이동한다. 시험 환경에서 리뷰를 작성하고 결과를 확인한다.

## 측정과 판정

작업별 성공·부분 성공·실패, 소요 시간, 도움 요청, 막힌 지점과 원인을 기록한다. 테스트 전에 성공 기준을 합의하고 실패 항목의 우선순위를 정해 수정 후 재검증한다.

# 결과 해석과 제출 전 확인

실행 성공, 사용자 경험, 공개 운영 준비는 서로 다른 검증 대상이다.

## 완료한 검증

핵심 저장 흐름과 입력 검증, 데이터 소유권 및 실제 AI 생성 성공을 확인했다. 테스트 중 예전의 상세 연결 전 상태를 기대한 오래된 이동 경로 테스트 한 개를 현재 기능에 맞게 수정하고 재실행했다.

## 추가 확인 범위

실사용자 5명 이상 결과와 배포 URL은 별도 수집·확인한다. 모바일과 PC에서 화면 전체를 클릭하며 폼과 팝업, 페이지 전환 및 날짜별 편집을 확인한다. 호스트 Agent의 실제 모델·언어·교차 계정 품질은 모의 검사와 구분한다.

## 발표 시 설명 원칙

임의의 만족도나 준비 시간 단축률을 넣지 않는다. 검색 추이는 전체 로그인 회원 기록, 개인화는 브라우저 이력임을 구분한다. 지도는 실제 도로 경로가 아니며 계절 키워드도 실시간 절정 확인이 아님을 설명한다.
