## 여행지 목록 수정 내용

1. 로컬 개발 서버의 외부 연결이 `EACCES`로 차단되는 문제를 정상 네트워크 실행 환경으로 재시작해 해소했다.
2. 실제 Supabase 조회에서 PostgreSQL `57014` statement timeout을 별도로 재현했다. 목록 데이터와 exact count를 결합한 조회를 분리했다.
3. 전체·지역별 건수는 기존 집계 RPC 결과를 5분간 재사용한다. 검색 건수는 동일한 검색어·지역의 HEAD exact count를 5분간 재사용한다. 페이지 데이터는 1분 캐시하며 동일한 진행 중 요청을 공유한다. 캐시는 서버 인스턴스별이다.
4. 분리만 한 첫 검증에서도 초기 요청 1건이 시간 초과되어, 읽기 SQL의 `57014`에 한해 150ms 후 한 번만 재시도하도록 보완했다. 권한 오류·다른 오류·쓰기 작업을 자동 재시도하지 않는다. 실패한 캐시 항목은 제거해 이후 재요청을 막지 않는다.
5. 시간 초과가 계속되면 503과 `Retry-After: 2`를 응답한다. 오류는 `no-store`로 캐시를 막고 내부 SQL 내용을 화면에 노출하지 않는다. 성공 응답은 기존 데이터 구조와 공개 키·RLS 접근을 유지한다. DB timeout 자체를 늘리거나 RLS를 우회하지 않았다.

## 검증 기록

수정 후 실제 로컬 API를 통한 Supabase 읽기 결과다. 환경·DB 부하에 따라 시간은 달라지며 아래 값이 최대 응답 시간을 보장하지는 않는다.

| 요청 | HTTP | 결과 | 소요 |
|---|---|---|---|
| 전체 1페이지 | 200 | 24건 / 전체 12,563곳 | 1,034ms |
| 전체 2페이지 | 200 | 24건 | 310ms |
| 전체 3페이지 | 200 | 24건 | 308ms |
| 제주 1페이지 | 200 | 24건 / 제주 557곳 | 167ms |
| 제주 ‘해변’ 검색 | 200 | 18건 / 검색 18곳 | 465ms |
| 같은 검색 2페이지 | 200 | 빈 페이지 / 검색 전체 수 18 유지 | 245ms |
| `%_` 문자열 검색 | 200 | 0건, SQL 와일드카드로 확대되지 않음 | 1,007ms |

목록 관련 테스트 17개와 Agent/오류 처리 테스트 29개, 합계 **46개 통과**. 웹 build와 lint는 종료 코드 0이다. 기존 다른 기능의 lint 경고와 번들 크기 경고는 남아 있다. 원격 DB에 테스트 데이터 생성이나 SQL 마이그레이션은 실행하지 않았다.

## 다음 작업 우선순위

1. 실제 참가자 테스트를 진행하고 원본 응답과 수집 시각을 보관한 다음, 보고서·발표자료의 문구를 그 증거에 맞춰 통일한다.
2. 로컬 Agent 변경을 대상 Edge Function에 반영할 배포 수단과 권한을 확보한 뒤, 승인된 HOST로 실제 실행을 검증한다. 현재 Dashboard의 배포본은 변경 전이다.
3. AI 일정 API 개선은 별도 과제로 보류한다. 인증 정책과 지속형 사용량 한도 설계, 서버 AI 키 설정, 지연 구간 측정이 선행되어야 한다.
4. 과거 자격 증명 조치는 사용자 확인상 통과로 기록했다. 보안 감사 증빙이 필요하면 관리자 확인 기록을 별도 첨부한다.
5. 가입 동의 정책·보유기간을 확정하고 SQL 영향과 Auth 가입 트리거 적용을 승인받은 뒤 원격 적용·신규 가입을 검증한다.
6. 평가 자료에는 원문 P0 표기 14건과 평가상 Must 분류를 구별해 반영한다. 평가 데이터는 소유자와 정리 기준을 확인하기 전 삭제하지 않는다.

## 사용자 확인 후 추가 보완

- 사용자가 실사용자 테스트 미실시를 확인했다. 피드백 Markdown을 정정하고 익명 참여자·수집 일시·응답 원문·개선 반영 기록 양식을 준비했다. 실제 5명 테스트 완료로 표시하지 않았다.
- 공통 `ExperienceDetailContent.jsx`와 `LanguageFriendsDemoDetail.jsx`에서 첨부된 상단 시연 안내 박스를 제거했다. 공통 컴포넌트가 적용되는 HOST 상세 미리보기도 같은 변경을 사용한다. 브라우저에서 체험 112의 정상 상세 로딩과 해당 박스 DOM 0개를 확인했다. 데이터의 시연 속성이나 이미지의 AI 생성 표시를 바꾸지는 않았다.
- 회원가입에 `/terms`, `/privacy` 초안 링크와 필수 동의 두 항목을 추가했다. 문의 이메일은 사용자 제공값을 사용한다. 신규가입 metadata에 동의값·문서 버전을 담고, 별도 원본 기록 테이블·Auth 트리거 SQL은 로컬 PostgreSQL에서만 검증했다.
- 이번 추가 변경 파일은 `src/App.jsx`, `src/pages/Signup.jsx`, `signupForm.js`, `ServicePolicy.jsx`, `ServicePolicy.css`, `shared/servicePolicies.js`, 공통 상세 컴포넌트 두 개 및 관련 테스트다. SQL 위치는 `docs/reviews/20261107_signup_consent.review.sql`이다.
- 잠금 파일 기준 의존성을 설치한 뒤, 목록·Agent·가입·동의 SQL 관련 테스트 **50개 통과**, build·lint 종료 코드 0을 확인했다. 기존 다른 영역의 lint 경고와 번들 크기 경고는 남아 있다. `package.json`과 `package-lock.json`은 변경하지 않았다.
- API 보호는 [권장 방향](reviews/20261107_api-auth-and-consent.md)만 제안했다. 실제 일정 생성 API 인증·전역 한도 적용은 아직 하지 않았다.
- 현재 실행 설명은 Supabase Auth·PostgreSQL 기준으로 통일했다. 과거 공개 이력의 비밀정보 조치 여부는 현재 DB 전환과 별도로 확인해야 한다.
- 현재 로컬 `.env.local`에는 `SUPABASE_SECRET_KEY` 항목이 있지만, 이 점검은 값이나 유효성 검증을 하지 않았다. `CODYSSEY_OPENAI_KEY`는 설정되어 있지 않다. 실제 키 값은 문서·채팅·프런트 코드에 쓰지 않는다.
