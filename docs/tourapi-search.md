# TourAPI 검색 연동

## 선택 및 키 설정

서버는 저장소를 `TRAVEL_SEARCH_DATA_SOURCE` 값으로 선택합니다.

- `example`: 기존 화면 확인용 예시 카탈로그
- `tourapi`: 한국관광공사 국문 관광정보 서비스 TourAPI

프로젝트 루트의 `.env.example`을 참고해 프로젝트 루트 `.env`에 위 선택값, `TOUR_API_SERVICE_KEY`, `TOUR_API_MOBILE_APP`를 입력합니다. 키는 서버 전용이며 브라우저 번들에 넣지 않습니다. 인증키는 공공데이터포털에서 **한국관광공사_국문 관광정보 서비스_GW** 활용을 신청해 발급받습니다. `TOUR_API_MOBILE_APP`에는 개발계정 사용 이력을 구분할 수 있는 프로젝트 앱 이름을 설정합니다. 신청/승인 상태와 개발·운영 트래픽 한도를 확인하고, 운영 전에는 공공데이터포털의 최신 이용 조건을 확인하세요. 실제 키는 저장소에 넣지 마세요.

## 검색과 조건 처리

공식 서비스는 지역코드 조회, 서비스분류코드 조회, 지역기반 검색(`areaBasedList2`), 키워드 검색(`searchKeyword2`), 숙박 검색(`searchStay2`), 공통·소개·이미지 세부정보 조회 등을 제공합니다. 현재 구현은 `areaBasedList2` 또는 `searchKeyword2`를 호출합니다. 지역은 TourAPI 지역코드로 제한하고, 큰 분류는 콘텐츠 유형 ID(관광지 12, 숙박 32)로 제한합니다. 테마와 일반 키워드는 별도 키워드 검색 요청으로 보내고 응답을 합친 다음 기존 공통 필터로 모든 조건을 다시 확인합니다. 따라서 “경남 바다 펜션”을 단일 자연어 키워드로 처리하지 않습니다.

TourAPI의 `contentTypeId=32`는 숙박 대분류이며 이것만으로 펜션·호텔·모텔 등의 세부 유형을 판별하지 않습니다. 현재 세부 유형은 응답의 제목/분류 문자열에서 직접 확인된 경우만 일치 처리합니다. 원천에 분류명이 오지 않으면 유형 조건을 만족한다고 꾸미지 않습니다. 같은 원칙으로 테마 태그도 제목·주소·응답 분류 문자열에 나타난 경우만 부여합니다. 외부 데이터 키는 `sourceCode=KTO_TOURAPI`, `sourcePlaceId=contentid`로 유지합니다. API 결과의 화면용 `id`에는 `tourapi:` 접두어를 붙이며 팀 PLACE_ID로 변환하지 않습니다. 상세페이지 이동은 계속 준비 중 안내로 남습니다.

## 페이지 수와 실패 처리

검색은 키워드별 최대 3페이지, 페이지당 최대 100건을 확인합니다. 결과가 잘린 경우 응답의 `matchCountComplete`가 `false`이고 화면은 “조회 범위 내 조건 일치” 건수로 표시합니다. 이는 전체 일치 건수나 전국 인기 통계가 아닙니다. 모든 조회 범위를 확인한 경우에도 `matchedCount`는 API 원천 조회 범위 안에서 공통 조건을 통과한 건수입니다. `returnedCount`는 화면에 보낸 건수입니다.

각 호출은 8초 제한을 적용합니다. 시간 초과, HTTP/응답 오류, 인증 오류, 일일 또는 초당 호출 한도 초과는 HTTP 오류 응답으로 돌려주며 0건 검색으로 바꾸지 않습니다. 결과에 사진이 없으면 이미지 URL을 `null`로 두어 화면에서 “사진 준비 중”을 표시합니다. 이미지 URL이 있는 경우 `photoSource`에 TourAPI 출처를 표시합니다.

모의 응답 검증은 `node --test server/repositories/tourApiRepository.test.js`로 실행합니다. 이 테스트는 실제 외부 요청을 보내지 않습니다. 개인화·검색 기록·LLM 및 상세페이지 연동은 이 단계에 포함하지 않습니다.
