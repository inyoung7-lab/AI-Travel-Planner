# 로컬이음 호스트 운영센터 및 회차 운영 설계

## 목표

호스트가 자신의 체험과 회차를 관리하고, 신청 현황을 확인할 수 있는 운영 진입점을 제공한다. 회차 추가·취소 동작은 Supabase 실제 저장과 맞물리며, AI 체험 진단은 함수 미배포와 호출 오류를 구분해 안내한다.

## 현재 확인된 상태

- `SessionEdit.jsx`는 회차 추가와 회차 단위 취소 UI를 이미 갖고 있지만, 회차 INSERT 정책과 `CANCELLED` 상태 제약이 원격 Supabase에 적용되지 않아 실제 저장/취소가 거부될 수 있다.
- 현재 `lc_sessions.status`는 `DRAFT`, `RECRUITING`만 허용한다. `lc_experiences.status`는 `DRAFT`, `PUBLISHED`만 허용한다.
- AI 화면은 `local-eum-agent` Edge Function을 호출한다. 지정 프로젝트에서 해당 경로가 404였고 함수 목록도 비어 있어, 앱 코드보다 함수 배포 누락이 현재 직접 원인이다.
- 신청 테이블은 `PENDING` 신청과 `DEMO_ONLY` 결제만 지원한다. 호스트는 소유 체험의 신청을 조회할 수 있지만 승인/거절/연락 이력 기능은 현재 스키마에 없다.
- 기존 브랜치 `hykang`에는 이 요청과 무관한 스테이징·미커밋 변경이 다수 있다. 기존 변경을 정리하거나 커밋하지 않는다.

## 화면 및 동작

### AI 체험 진단

- 함수가 연결되지 않을 때 일반적인 재시도 안내 대신 배포 누락, Origin/CORS, 인증, upstream API 오류를 구분 가능한 메시지로 표시한다.
- 오류 메시지는 키, 헤더, 민감한 요청 본문을 노출하지 않는다.
- Edge Function의 TypeScript 코드는 유지한다. 함수 배포는 사용자 로컬의 Supabase CLI 인증이 필요하므로 로컬 구현과 배포 안내를 분리한다.

### 회차 생성 및 취소

- 회차 생성 성공 시 새 회차 ID를 선택해 편집 화면으로 이동하고, 목록에도 저장된 회차가 표시되어야 한다.
- 회차 INSERT는 인증된 소유 HOST가 자기 체험에 `DRAFT` 회차를 만들 때만 허용한다. ADMIN 동작은 기존 정책을 따른다.
- 회차 취소는 선택한 회차만 `CANCELLED`로 표시한다. 기존 신청 기록을 보존하고 이후 신청 접수는 RPC의 모집 상태 검증으로 차단한다.
- 체험 취소는 체험을 `CANCELLED`로 전환하고, 시작 전 회차를 한 트랜잭션에서 함께 취소한다. 이미 시작한 회차와 모든 신청/결제 기록은 보존한다. 환불이나 참가자 알림은 자동 실행하지 않는다.
- 체험/회차 취소에는 확인 단계를 둔다. 취소된 자료는 삭제하지 않으며 운영센터에서 상태를 확인할 수 있다.

### 호스트 운영센터

- 기존 `/local-eum/host/profile` 경로를 운영센터 진입점으로 사용해 `App.jsx`와 공통 `Header`를 수정하지 않는다.
- 화면에는 운영 요약, 내 체험, 내 신청함, 호스트 프로필 편집 영역을 둔다.
- 본인 소유 체험 및 세션, 본인 체험에 속한 신청만 조회한다. 데이터 접근은 현재 Supabase RLS가 강제한다.
- 신청함은 현재 스키마가 제공하는 신청 현황만 표시한다. 승인/거절/연락 이력을 만들어내거나 모의 상태로 표현하지 않는다.
- 다른 HOST의 체험 및 신청은 조회·수정할 수 없어야 한다.

## 데이터 및 배포 변경

- 기존 체험, 호스트, 신청, 결제 행을 새로 생성하거나 삭제하지 않는다.
- 검토용 SQL은 대상 프로젝트 `rhkaxmqdkztpbljkunxb`와 현재 제약/정책 이름 및 소유 관계를 검사한다. 예상과 다른 상태이면 트랜잭션을 중단한다.
- SQL 변경안은 회차 INSERT 정책과 상태 제약, 소유자 권한이 제한된 체험 취소 RPC를 포함한다. 운영센터 조회는 기존 RLS 정책을 재사용한다.
- 원격 Supabase SQL 적용은 사용자가 SQL 전문과 대상 프로젝트를 확인한 뒤 별도 승인해야 한다.
- `local-eum-agent` 배포에는 Supabase CLI 로그인 권한이 필요하다. 가상 API 키는 소스·문서·브라우저에 기록하지 않는다.

## 변경 경계

- 예상 React 변경: `SessionEdit.jsx`, `sessionRepository.js`, `HostProfileEdit.jsx` 및 필요한 페이지 스타일/검증 파일.
- SQL은 검토용 migration 초안으로 작성한다. 승인 전 원격 DB에 적용하지 않는다.
- `Header`, `App.jsx`, Oracle 관련 파일, 기존 커밋 및 기존 미커밋 작업은 수정하지 않는다.
- 커밋, push, merge, 이미지 교체는 이 작업에 포함하지 않는다.

## 검증 기준

1. 회차 생성 성공·권한 거부·네트워크 오류가 구분되고, 성공 후 DB에서 다시 읽은 회차가 선택된다.
2. 회차 취소는 해당 회차에만 적용되고, 취소된 회차의 신청 CTA가 사라진다.
3. 체험 취소는 향후 회차를 원자적으로 취소하며 신청 기록은 그대로 유지된다.
4. HOST 운영센터는 로그인 HOST의 소유 체험과 신청만 보여준다. 로그아웃/비 HOST/다른 HOST의 데이터 경로는 거부된다.
5. Edge Function이 미배포된 상태에서 화면은 배포 누락을 알아볼 수 있게 설명하고, 민감정보를 노출하지 않는다.
6. 관련 단위 테스트, `npm run lint`, `npm run build`가 통과한다. 기존 경고는 신규 회귀와 구분해 보고한다.
7. 기존 브랜치 변경의 stage 상태를 보존하고, 이번 작업 파일을 임의로 stage/commit/push하지 않는다.

## 미해결 의존성

- AI 진단의 실제 성공 검증에는 Edge Function 배포가 필요하다. Supabase CLI 로그인 준비가 안 되어 있으면 UI 오류 처리는 로컬에서 검증하고, 배포 성공으로 보고하지 않는다.
- 회차 추가와 취소의 실제 DB 검증에는 별도 승인된 migration 적용이 필요하다. 적용 전에는 로컬 모의 테스트와 SQL 정적 검토만 수행한다.
