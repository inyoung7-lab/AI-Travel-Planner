# HOST AI 개발 검증 기록과 외부 확인 안내

## 확보된 개발 검증 증거

승인된 기존 HOST가 로그인한 로컬 `main` 화면에서 Supabase `local-eum-dev` (`rhkaxmqdkztpbljkunxb`)의 기존 배포 함수 `local-eum-agent`를 호출했다. 아래 결과는 도구 선택 구조를 바꾸기 **전의 배포 함수**에 대한 기록이다.

| 과제 | 실제 결과 | 서버 응답 시간 | 확보 근거 |
|---|---|---|---|
| 마산 창동예술촌 아트워크 / 회차 12 분석 | HTTP 200, 보고서·평가·비용·근거·개선안 표시 | 약 12.2초 | 브라우저 Network 응답, 생성 시각 `2026-11-07T05:44:35.947Z`, 네 도구 실행 trace, 화면 확인 |
| 공개 골목의 문화 관찰·기록 모임 아이디어 분석 | HTTP 200, 보고서·근거·개선안 표시 | 약 11.2초 | 브라우저 Network 응답과 결과 화면 확인. 정확한 서버 생성 시각은 별도 보존하지 않음 |

위 내용은 대화에서 직접 관찰한 개발 실행 기록이다. 원본 HAR/영상 파일은 별도 저장하지 않았으므로 제출용 원본 파일이 확보됐다고 표시하지 않는다. 비밀번호·JWT·응답 전체·신청자 개인정보는 이 문서에 넣지 않는다. 이전에 사용자가 겪은 실패는 이번 두 요청에서 재현되지 않았고 당시 오류 원인은 확정하지 않았다.

## 외부 평가자 확인 절차

1. 팀 배포 주소의 `/local-eum/host/profile`을 연다. 로컬 개발 주소는 해당 PC에서만 사용할 수 있다.
2. 담당자가 기존 승인 HOST로 로그인해 동반 시연하거나, 평가용 접근 정보를 승인된 비공개 방식으로 전달한다. 공개 데모는 읽기 전용이므로 실제 AI 실행 증거와 구분한다.
3. 본인 체험·회차를 고르고 AI 기획·진단 → 현재 체험 분석을 실행한다.
4. 보고서·평가·비용·근거 링크·개선안과 ‘실행한 도구’를 확인한다. 새 아이디어 분석도 별도로 실행한다.
5. 화면·비식별 실행 로그·실행 시각을 저장한다. Network 요청 헤더와 HAR에는 JWT가 들어갈 수 있으므로 원본을 공개 GitHub에 올리지 않는다.
6. 새 모델 선택 함수가 배포된 뒤에는 응답의 `execution.strategy = model_selected_json_actions`와 순서별 선택 이유를 확인한다. 현재 확보된 구함수 결과를 새 함수의 실제 모델 검증으로 대체하지 않는다.

**주의:** 이 문서의 두 실제 HOST 호출은 모델 선택형 구조로 바꾸기 전의 배포 함수 기록이다. 별도 설문으로 진행한 실제 사용자 5명 테스트는 완료되어 [실사용자 결과](../user-test-results-20261108.md)에 기록했다. 최신 Agent 구조의 원격 배포·HOST 실행은 여전히 확인되지 않았다.
