# 로컬이음 여행자 AI 안내 — 채널톡 벤치마킹 검토

## 결론

채널톡 화면의 채팅 위젯만 복제하지 않고, **질문 → 검증된 체험·회차 조회 → 출처가 보이는 답변 → 신청 화면 이동 또는 HOST 연결**을 로컬이음 안에서 구현한다. 지금의 `AiExperienceAgent`는 HOST의 체험 기획·진단용이므로 여행자 상담과 별도 기능으로 둔다. 채널톡 계정 생성이나 외부 위젯 설치는 첫 단계에 필요하지 않다.

채널톡의 공식 설명에서 벤치마킹할 기능은 웹 버튼, 상황별 규칙, 참조 지식, 업무 태스크, 상담원 연결, 배포 전 시나리오 테스트다. 로컬이음은 이를 여행 맥락에 맞게 좁혀 적용한다.

## 여행자 화면과 대화 예시

- `/local-eum`과 공개 체험 상세에 작고 접근 가능한 `AI 여행 안내` 버튼을 둔다. 열면 “체험을 찾거나 날짜·집결지·준비물을 물어보세요”라는 인사와 예시 질문 3개를 보여준다. 모바일에서는 화면을 가리지 않는 전체 높이 시트로 연다.
- 상세에서 열면 현재 `experience_id`와 선택 `session_id`를 **힌트**로 전달한다. 서버는 그 ID로 공개 상태를 재조회한다. URL의 텍스트나 모델 응답을 사실로 신뢰하지 않는다.
- 질문 예: “12월 13일 비밀지도는 몇 시에 모여요?” → 공개된 회차·집결지 조회 → 날짜와 장소를 명시하고 체험 상세 링크 표시. “아이와 참여할 수 있나요?” → 확정된 연령 정책이 없으면 추측하지 않고 HOST 확인이 필요하다고 답변. “신청해 줘” → 모집 중인 회차를 확인하고 기존 신청 화면으로 이동할 버튼 제공. 사용자의 명시적 제출 없이 신청 RPC를 호출하지 않는다.
- 답변 아래에 `AI가 생성한 안내`, 사용한 체험·회차 또는 공공 출처, 정보 확인 시점을 표시한다. 시연 상품에는 `실제 예약·결제 불가`를 유지한다.
- 한국어·영어·일본어는 기존 로컬이음 언어 선택을 따른다. 장소명·날짜·금액·ID는 번역 과정에서 바꾸지 않는다.

## 기능 단계

| 단계 | 기능 | 완료 조건 |
| --- | --- | --- |
| 1 | 공개 체험 검색, 일정·가격·장소·준비물 질의응답, 근거 링크, 기존 신청 화면 연결 | 공개된 행만 조회하고, 사실이 없으면 확인 필요라고 답함 |
| 2 | `HOST에게 문의` 전달과 운영센터 상담함 | 공개 정보로 해결할 수 없는 질문을 해당 체험 소유 HOST에게만 전달; 수신·답변 상태 확인 |
| 3 | 본인 신청 상태 조회, 변경 요청 등 제한된 태스크 | 로그인 또는 접수번호와 별도 인증으로 본인 확인 후 실행; 취소·결제는 정책과 승인 절차가 정해진 뒤만 허용 |

초기 버전은 자동 신청, 자동 취소, 카드 결제, 가상계좌 발급, 외부 메신저 발송을 수행하지 않는다. HOST 연결을 구현하기 전에는 `HOST에게 문의` 버튼을 실제 전송 기능처럼 표시하지 않는다.

## 구현 경계

1. React `TravelerAgentWidget`를 로컬이음 공개 경로에만 배치한다. 공통 `Header`와 다른 여행 서비스 화면은 수정 대상에서 제외한다.
2. 별도 Supabase Edge Function `local-eum-traveler-agent`가 질문 길이·요청 빈도·허용 origin을 검사한다. Codyssey 비밀키는 Edge Secrets에만 둔다. 기존 HOST용 함수의 JWT·소유권 가드를 여행자용으로 재사용하지 않고, 공개 데이터 전용 조회와 인증이 필요한 태스크를 분리한다.
3. 현재 Codyssey 연결에서는 기본 채팅이 성공하고 네이티브 도구 호출이 `unsupported_feature`로 거절되었다. 따라서 모델은 조회할 조건만 JSON으로 제안하고 서버가 허용된 읽기 도구를 실행한다. 최종 답변의 ID·날짜·회비·출처는 서버가 검증된 조회 결과와 대조한다.
4. 자료 원본은 `lc_experiences`, `lc_sessions`, `lc_experience_steps`, 공개 `lc_hosts`, `lc_places`의 공개 가능한 필드와 운영자가 검수한 정책 FAQ다. 체험 소유·비공개 행·신청자 개인정보는 일반 질문의 검색 대상에서 제외한다. 최신 회차 상태는 대화마다 DB에서 다시 읽는다.
5. 대화 저장은 동의, 보유기간, HOST별 접근 권한을 정한 뒤 별도 테이블과 RLS로 도입한다. MVP에서는 최소한의 비식별 오류·도구 추적만 남긴다. 상담원 인계 시 AI 요약은 원문과 구분하며 HOST가 본인 체험 문의만 볼 수 있게 한다.

## 검증 시나리오

- 공개 모집 회차의 날짜·시간·회비와 체험 상세의 표시가 일치한다.
- 취소·종료·비공개 회차는 모집 중이라고 답하지 않는다.
- 식품 알레르기, 미확정 시식 제휴, 시설 관람료 등 없는 정책을 만들어내지 않는다.
- 비회원이 타인의 신청 상태를 묻거나 다른 HOST의 비공개 데이터를 요청하면 거절한다.
- 한국어·영어·일본어 질문에 각 언어로 답하고 숫자·주소·고유명사를 보존한다.
- 모델 장애 시 검증되지 않은 답을 표시하지 않고 체험 상세와 HOST 문의 경로를 안내한다.
- 실사용자 5명 이상이 체험 찾기·일정 확인·신청 화면 이동을 수행한 뒤 성공률, 오류 답변, 이해도 피드백을 기록한다.
