# 로컬이음(LOCAL EUM) — 기획·구현 완료 보고서

**관광지에서 사람으로, 정보에서 경험으로**
> 여행에서 만남으로, 만남에서 새로운 경험으로.

## 프로젝트 개요

로컬이음은 국내외 여행자와 지역 주민을 연결해 지역의 시장·골목·문화와 일상을 함께 경험하도록 돕는 로컬 체험 서비스입니다. 기존 여행 서비스가 주로 어디를 방문하고 무엇을 볼지 안내하는 데 집중한다면, 로컬이음은 그곳에서 누구를 만나고 무엇을 함께 경험할 수 있는가라는 질문에서 출발했습니다.

여행자는 지역 주민과 시장을 걷고, 음식을 나누고, 언어와 문화를 교류하며 새로운 경험을 발견합니다. 지역 주민은 전문 관광 안내자가 아니더라도 자신의 이야기와 관심사를 바탕으로 여행 경험을 만드는 호스트가 됩니다. 로컬이음이 연결하는 것은 단순한 관광 정보가 아니라 사람과 사람, 그리고 함께 만드는 경험입니다.

## 기획에서 구현까지

처음에는 LOCAL CONNECT라는 이름으로 지역 주민과 여행자가 함께 참여하는 프로그램을 구상했습니다. 시장·음식, 골목 탐방, 언어·친구, 공예, 자연, 취미와 지역 일상을 검토한 뒤, 로컬이음이라는 이름으로 실제 웹서비스의 이용 흐름과 운영 기능을 구체화했습니다.

| 단계 | 구현 내용 |
| --- | --- |
| 기획 | 관광지 방문 중심에서 지역 주민과 함께하는 경험으로 방향 확장 |
| 화면 설계 | 체험 검색, 상세 정보, 회차 선택, 신청, 호스트 화면 설계 |
| 데이터 연결 | Supabase로 호스트·체험·회차·신청 데이터 관리 |
| 운영 기능 | 호스트 프로필·프로그램·회차·신청자 관리 |
| 사용자 편의 | 한국어·영어·일본어 화면, 주소 기반 Kakao 지도 검색 |
| AI 활용 | 호스트의 체험 아이디어와 상품 가치를 검토하는 기획 Agent |

화면을 만드는 데서 그치지 않고, 사용자 입력이 데이터로 저장되고 권한에 따라 처리되며 AI 기능과 연결되는 흐름을 구현했습니다.

## 완성된 이용 흐름과 기능

여행자는 지역과 관심 분야로 체험을 탐색하고 상세 정보, 호스트, 운영 회차를 확인한 뒤 참가 신청을 제출합니다. 신청 정보는 Supabase에 저장되고 접수 내용을 확인할 수 있습니다.

호스트는 로그인 후 프로필과 프로그램을 관리하고 회차를 운영하며 신청 현황을 확인합니다. 호스트 운영 화면에는 프로그램·회차 관리, 신청자 연락처 확인, AI 기획 지원이 연결되어 있습니다.

화면 언어는 한국어·영어·일본어를 지원합니다. 화면을 번역해 표시하는 기능과 호스트가 실제 체험에서 사용할 수 있는 진행 언어는 별도로 관리합니다. 장소는 주소 정보를 표시하고 Kakao 지도에서 검색할 수 있도록 연결했습니다.

## AI Agent를 도입한 이유

지역의 장소나 활동을 프로그램으로 등록하는 것만으로는 여행자가 참여하고 싶어 하는 경험이 만들어지지 않는다는 점을 발견했습니다. 이에 AI Agent가 기존 체험과 지역 자료를 살펴 고객에게 제공할 가치, 차별화 아이디어, 예상 비용과 운영상 유의점을 제안하도록 구성했습니다.

AI는 호스트의 기획을 돕는 도구입니다. 결과를 자동으로 확정하거나 저장하지 않으며, 호스트가 근거와 제안을 검토하고 편집한 뒤 활용합니다. 이를 통해 AI를 글쓰기 보조에 그치지 않고 실제 데이터와 연결된 기획 지원 도구로 사용하는 방식을 구현했습니다.

## 기술 구성과 데이터 현황

- 프런트엔드: React, Vite, JavaScript, CSS
- 데이터베이스: Supabase PostgreSQL
- 인증·접근 제어: Supabase Auth, HOST/ADMIN 역할, Row Level Security
- 이미지: Supabase Storage
- AI: Supabase Edge Function과 Codyssey API 연동
- 지도: 주소 기반 Kakao 지도 검색

2026년 10월 20일 개발 DB의 읽기 전용 조회 기준으로 호스트 2명, 체험 15개, 운영 회차 19개가 등록되어 있습니다. 이 수치는 개발 DB 조회 시점의 데이터 현황입니다.

## 결과와 배운 점

로컬이음은 체험 탐색부터 상세 확인, 신청, 호스트 운영, AI 기획 지원까지 하나의 웹서비스 흐름으로 구현됐습니다. 화면·데이터·권한·다국어·장소·AI가 각각 분리된 기능에 머물지 않고, 처음 정의한 문제를 풀도록 연결하는 과정을 경험했습니다.

특히 데이터베이스를 크게 설계하는 것보다 사용자의 업무 흐름을 먼저 이해하는 일이 중요하다는 점을 배웠습니다. 기능을 더하는 것 자체보다 여행자와 호스트가 실제로 이용할 흐름을 정하고, 그 흐름에 필요한 데이터와 권한 처리를 연결하는 것이 서비스 구현의 핵심이었습니다.

## 구현 범위 안내

참가 신청 접수와 회비 표시 기능은 구현되어 있지만 실제 결제·환불·정산 기능은 제공하지 않습니다. 화면의 시연 데이터와 개발 DB 데이터는 구분하며, 개발 DB 수치를 실제 상용 서비스의 이용 실적으로 표현하지 않습니다.



**LOCAL EUM — 여행의 장소를 넘어, 사람과 경험을 연결하다.**
