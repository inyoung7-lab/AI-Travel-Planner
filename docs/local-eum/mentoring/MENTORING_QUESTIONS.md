# 멘토링 질문과 의사결정

## 1. 고객 가치와 가격 — 최우선

**현재 근거:** 체험 목록·상세·회차·신청 UI가 있고, 3개 시범 체험은 공개 상태입니다. 사용자가 실제로 비용을 지불한 사례는 확인되지 않았습니다. 부산 체험은 표시 비용이 0원이고 다른 두 체험은 표시 비용이 있습니다.

**선택지:** (A) 가격 의향 인터뷰 후 한 회차를 소규모 유료 파일럿으로 검증, (B) 무료 체험으로 신청 장벽과 관심도만 먼저 측정, (C) 호스트 설명·결과물·포함 사항을 개선한 다음 가격을 다시 묻기.

**질문:** 캡스톤 기간에 지불 의사를 신뢰성 있게 확인할 가장 작은 실험과 성공 기준은 무엇인가요?

## 2. 실제 HOST 운영의 최소 검증

**현재 근거:** 회차 생성·취소를 위한 화면, SQL 권한 정책과 RPC가 있고 테스트 전용 데이터로 일부 HOST 흐름을 확인했습니다. 교차 HOST의 직접 API 수정 거부와 ADMIN 실사용 전체 경로는 제한적으로 검증됐습니다.

**선택지:** 실제 프로그램 1개 운영 리허설, 테스트 전용 DRAFT만으로 권한·취소를 추가 검증, 혹은 실 사용자 테스트보다 운영 정책·장소 허가 확인을 먼저 진행.

**질문:** 어떤 조작과 증거가 있어야 “HOST 운영 가능”이라고 말할 수 있나요?

## 3. AI Agent 구조와 평가

**현재 근거:** 네 개 도구를 Edge Function에서 검증·실행하고, COPA 응답의 JSON 인자를 어댑터로 처리합니다. 네이티브 Tool Calling은 사용하지 않습니다. 모의 모델 단위 테스트는 실제 모델의 정확성·가격 적합성을 증명하지 않습니다.

**선택지:** 현재 어댑터를 우선 고도화, 네이티브 도구 호출 지원 제공자를 실험 비교, 또는 AI 범위를 아이디어 초안과 검토 체크리스트로 축소.

**질문:** 실제 모델의 근거 충실도·오답·비용을 비교할 평가 데이터와 중단 기준을 어떻게 정할까요?

## 4. RAG 데이터의 범위·신뢰성

**현재 근거:** 지역 지식 문서와 URL·확인일을 바탕으로 검색 근거를 제시합니다. 현재 corpus는 실제 제휴·영업·원가·시설 허가를 증명하지 않습니다.

**선택지:** 출처가 분명한 공공 자료만 좁게 유지, HOST가 확인한 운영 지식을 추가, 현장 확인 기록을 별도 자료로 관리.

**질문:** 출처의 최신성·지역 커버리지·근거 부족 판단을 어떤 기준으로 운영할까요?

## 5. 팀 통합과 출시 경계

**현재 근거:** 공통 Header와 React Router에서 로컬이음으로 이동합니다. 로컬이음 데이터는 Supabase이고 팀의 일부 기능은 Express·Oracle을 사용합니다. 동일 로그인·통합 배포의 계약은 별도로 합의해야 합니다.

**선택지:** Supabase HOST 로그인과 기존 팀 회원을 당분간 분리, 팀 인증을 공통 identity로 연결, 또는 통합 뒤에도 Supabase의 HOST role/RLS를 독립 유지.

**질문:** 캡스톤에서 통합해야 할 최소 경계는 메뉴·배포·인증 중 어디이며, 어떤 것은 독립 유지해야 할까요?
