# LOCAL EUM 멘토링 요약

## 한 문장 소개

지역 호스트의 관점과 참여 활동을 체험으로 구성해 국내외 여행자가 탐색·신청하고, 호스트가 프로그램·회차·신청자를 관리하도록 돕는 로컬 체험 서비스입니다.

## 대상과 문제

- 여행자: 지역 주민과 함께할 만한 활동을 찾고, 가격·시간·진행 언어·집결 정보를 신뢰할 수 있게 비교하고 싶습니다.
- HOST: 아이디어를 일정·장소·안전·가격으로 구체화하고, 여러 회차와 신청자를 관리해야 합니다.
- 핵심 가설: 단순 장소 방문이 아니라 호스트의 해석, 참여 방식, 기억할 결과가 비용을 지불할 이유인지 검증해야 합니다.

## 현재 구현

공통 React/Vite 앱 안에 체험 목록·상세·신청 흐름, HOST 프로필·프로그램·회차·신청자 운영센터, 한국어·영어·일본어 표시, 영어·일본어 번역 초안, 주소 기반 Kakao Maps 연결, Codyssey 기반 AI 기획·진단 Agent가 있습니다. 로컬이음 DB는 Supabase PostgreSQL/Auth/RLS/Storage/Edge Functions를 사용합니다. 팀의 다른 기능은 Express·Oracle과 별도 운영될 수 있습니다.

2026-10-20 read-only 조회에서 호스트 2명, 체험 15개, 일정 단계 68개, 운영 회차 19개, 신청 1건, 시연 결제 안내 1건을 확인했습니다. 서울·부산·창원 언어·친구 3개는 공개 상태이며 연결 회차도 모집 중입니다. 세 체험의 실제 진행 가능 언어는 HOST 확인 전 빈 배열입니다.

## 기술 선택과 경계

공통 React 화면은 기존 라우터·Header와 연결하고, 로컬이음 업무 데이터는 Supabase RLS로 분리합니다. AI는 서버가 허용된 검색·RAG·가치 평가·비용 산식 도구를 순서대로 실행하는 구조입니다. COPA 네이티브 Tool Calling 대신 일반 채팅 JSON을 제한적으로 해석하는 어댑터를 씁니다. Agent 결과는 자동 저장되지 않으며 HOST 검토 후 기존 저장 흐름을 거칩니다.

신청 접수는 구현되어 있지만 결제·환불·정산은 실제 기능이 아닙니다. 번역 초안은 검수 전 DRAFT이며 화면 언어가 실제 진행 언어를 의미하지 않습니다. 공개 운영센터는 가상 데이터의 읽기 전용 데모입니다.

## 멘토링에서 결정할 것

1. 고객의 지불 이유와 가격을 어떤 작은 실험으로 검증할 것인가?
2. 다음 2주 동안 실 HOST 운영에서 가장 먼저 확인해야 할 조건은 무엇인가?
3. Agent의 도구·RAG 근거·비용·품질을 어떤 평가 기준으로 검증할 것인가?
4. 팀 로그인·공통 배포와 로컬이음 HOST 권한을 어디까지 통합할 것인가?

## 다음 제안

기능을 더 늘리기보다 HOST가 진행 언어·회비·장소를 확인하고, 여행자 소규모 테스트에서 가치·혼동·신청 성공률을 관찰합니다. 그 결과에 맞춰 Agent 평가와 통합 배포 범위를 결정합니다. 외부 사용자 테스트와 피드백 반영은 아직 완료된 것으로 볼 수 없습니다.
