# 로컬이음 HOST 운영 기능 실계정 검증 기록 (2026-10-20)

## 범위와 사전 보호

- 원격 프로젝트: `local-eum-dev` (`rhkaxmqdkztpbljkunxb`). 기존 SQL 마이그레이션은 재실행하지 않았다.
- 승인된 기존 HOST #500과 #501을 사용했다. ADMIN 계정은 생성하거나 시험하지 않았다.
- 시험 전 원격 데이터: `lc_experiences` 15건, `lc_sessions` 19건, `lc_applications` 1건, `lc_application_payments` 1건.
- 네 테이블의 기존 행 전체를 Windows 현재 사용자 DPAPI로 암호화해 저장했고, 같은 사용자 환경에서 복호화·행 수를 검증했다. 백업 및 시험 SQL은 Git 저장소 밖의 사용자 로컬 백업 폴더에 보관했다. 개인정보와 인증 정보, 개인 PC 경로는 이 문서에 기록하지 않는다.
- `900001`은 예약 ID가 아니라 시험 전용 `lc_experiences.experience_id`이다. 시험 시작 전 미사용 상태를 확인했다.

## 발견한 화면 개선점과 검증 한계

1. 첫 회차가 없는 체험에는 운영센터의 `운영 회차 추가` 진입점이 없다. 이번 시험은 전용 체험에 기준 회차 1건을 먼저 만든 뒤 화면에서 두 번째 회차를 추가했다.
2. 다른 HOST가 회차 편집 URL을 직접 열면 정상적으로 조회가 차단되지만, 화면에는 `Cannot coerce the result to a single JSON object`라는 원시 오류가 나타난다. 권한 없음 또는 조회 불가 안내로 바꾸는 개선이 필요하다.
3. 실제 HOST #501 계정으로는 화면 접근 차단을 확인했다. 직접 UPDATE HTTP 요청은 UI가 편집 폼을 제공하지 않아 보내지 않았고, RLS UPDATE 거부는 #501 클레임으로 실행한 롤백 시험으로 확인했다. 이 두 결과를 혼동하지 않는다.
4. ADMIN 계정의 회차 생성·취소와 기존 신청이 있는 회차의 취소 동작은 이번 승인 범위 밖이다.
