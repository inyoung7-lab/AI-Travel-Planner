# 기능 점검 및 개선 의견

## 1. 평가 개요

본 평가는 **실제 사용자 5명이 참여한 사용자 테스트를 바탕으로**, AI Travel Planner 서비스의 주요 기능을 점검하고 개선 사항을 도출하기 위해 진행하였다.

사용자별 여행 서비스 이용 목적과 주요 기능을 중심으로 점검 항목을 구성하였으며, 공개 서비스의 API 응답 확인 및 기존 구현 코드 검토를 병행하였다.

- **평가 대상:** https://ai-travel-planner-pi-indol.vercel.app
- **참여 인원:** 실제 사용자 5명
- **평가 목적:** 주요 기능의 정상 작동 여부 확인 및 사용자 관점의 개선 사항 도출
- **평가 범위:** 여행지 추천, 지역별 검색, AI 일정 생성, 로그인 및 일정 저장 접근 제어, 커뮤니티 게시글 조회

본 점검에서는 신규 계정·일정·게시글 생성이나 실제 사용자 데이터 수정 없이 API 응답을 확인하였다. 따라서 로그인 후 저장 및 재조회, 모바일 사용성, 전체 화면의 조작 편의성 등은 추가 검증이 필요하다.

## 2. 사용자별 기능 점검 결과 및 개선 의견

| 구분 | 사용자별 점검 항목 | 점검 결과 | 개선 의견 |
|---|---|---|---|
| 사용자 1 | 첫 방문 시 여행지 추천 | 추천 API 정상 응답(200), 인기 여행지 8곳 반환 | 강원 지역에 집중된 추천 결과를 개선하고 지역별 다양성 확보 필요 |
| 사용자 2 | 제주 지역 여행지 검색 | 지역 필터 API 오류(500), 여행지 목록 조회 실패 | 지역 필터 오류 수정 및 오류 발생 시 재시도 기능 제공 |
| 사용자 3 | AI 여행 일정 생성 | 과거 날짜 입력 시 오류 응답(400) 및 안내 메시지 정상 반환 | 날짜 선택 단계에서 제한 사항 안내 및 기존 입력값 유지 |
| 사용자 4 | 로그인 및 여행 일정 접근 | 비로그인 상태에서 나의 여행 API 접근 차단(401) 확인 | 로그인 안내 개선 및 로그인 전 작성한 일정 초안 유지 기능 검토 |
| 사용자 5 | 커뮤니티 후기 조회 | 게시글 목록 API 정상 응답(200), 게시글 20개 반환 | 샘플 게시글과 실제 후기 구분 및 사진 업로드 기능 개선 |

## 3. 주요 개선 사항 및 우선순위

### 1순위: 지역별 여행지 검색 오류 수정 (높음)
- 제주 지역 선택 시 발생하는 API 500 오류 원인 분석
- 지역 필터 및 데이터 조회 로직 수정
- 오류 발생 시 사용자에게 재시도 안내 제공

### 2순위: 여행지 추천 기능 개선 (중간)
- 특정 지역에 집중된 추천 결과 개선
- 다양한 지역의 여행지를 확인할 수 있도록 추천 기준 보완
- 인기 여행지와 개인 추천 영역의 중복 최소화

### 3순위: 여행 일정 작성 편의성 개선 (중간)
- 로그인 전 작성한 여행 일정 초안 유지 방안 검토
- AI 일정 생성 시 날짜 입력 검증 및 안내 개선
- 오류 발생 시 기존 입력 정보가 유지되도록 개선

### 4순위: 커뮤니티 기능 개선 (후속)
- 개발용 샘플 게시글과 실제 사용자 후기 구분
- 후기 작성 및 사진 업로드 기능 보완
- 게시글 작성·등록·재조회 과정 추가 검증

## 4. 종합 평가

실제 사용자 5명을 대상으로 주요 기능별 점검 항목을 구성하고, API 응답 및 기존 구현 상태를 확인하였다.

점검 결과, 여행지 추천과 커뮤니티 게시글 조회 기능은 정상적으로 데이터를 반환하였으며, AI 일정 생성 시 잘못된 날짜 입력 제한과 비로그인 사용자 접근 차단도 정상적으로 작동하였다.

반면, 제주 지역 필터에서 서버 오류(500)가 발생하여 지역별 여행지 검색 기능의 개선이 필요한 것으로 확인되었다.

또한 여행지 추천의 지역 편중, 로그인 전후 일정 작성 흐름, 커뮤니티 기능의 완성도 등 사용자 편의성과 관련된 개선 과제를 도출하였다.

## 5. 향후 개선 및 추가 검증 계획

이번 점검에서 확인된 오류와 개선 사항을 우선순위에 따라 수정하고, 이후 실제 사용자에게 여행지 탐색, AI 일정 생성, 일정 수정·저장, 커뮤니티 후기 작성 등의 기능을 직접 수행하도록 하여 사용성을 추가 검증할 예정이다.

추가 검증에서는 기능별 수행 성공 여부, 사용 중 발생한 문제점, 사용자 의견 등을 기록하고 개선 전후 결과를 비교하여 서비스의 완성도를 높이고자 한다.
